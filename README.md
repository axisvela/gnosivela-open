# GNOSIVELA-open

> **GNOSIVELA-open** �?Developer entry point and distribution surface (Apache-2.0).

[中文文档](./README.zh-CN.md)

GNOSIVELA is AxisVela's **Enterprise Semantic & Knowledge Fabric**: it turns how an enterprise defines concepts, unifies entity references, interprets relations, evidences claims, and governs conflicts into a consumable semantic layer. This repository is the public distribution surface: **SDKs, examples, API contract, reference ontology, and binary releases**.

## The problem it solves

Enterprise knowledge is scattered across ERP / CRM / documents / data lakes / policy stores, and every agent, planner, or BI tool guesses at meaning on its own. The result:

- **Same name, different meaning** �?three definitions of "Active Customer" coexist and no one knows which one is in use
- **Split identities** �?the same supplier has 12 IDs across 12 systems; cross-source merging is left to luck
- **Ungrounded answers** �?agents output plausible conclusions with no traceable source, time, or permission chain
- **Silently overwritten conflicts** �?new data replaces old data instead of being kept as competing assertions
- **Vendor lock-in** �?semantics get welded to the internal schema of a specific graph or vector store

GNOSIVELA's answer: define semantic objects first (Ontology / Assertion / Identity / Relation / Grounding), then decide on storage. The **semantic control plane** owns consistency and governance; the **polyglot projection** layer (SQL / Graph / Search / Vector) stays replaceable and never pollutes the semantic API.

## Features

| Capability | Description |
| --- | --- |
| Semantic Contract DSL | Declare concepts, properties, constraints, and relations; the DSL compiler generates SDK types + JSON Schema |
| Ontology Registry | Versioning / semantic diff / validation / publish / deprecate |
| Knowledge Assertion | Every claim carries source, time, context, status, confidence, and an evidence chain |
| Entity Identity | Cross-source entity resolution with exact-match and evidence-first merging; fuzzy matches are candidates only, never silently merged |
| Polyglot Projection | Same semantic object projected to Relational / Graph / Search / Vector; replaceable without exposing vendor types |
| Semantic Query | Intent parsing �?joint retrieval across entities/relations/documents/metrics �?purpose-scoped KnowledgeView with conflicts/gaps |
| Hybrid Retrieval | BM25 + vector + graph recall fused with RRF; component scores/ranks via `POST /query/hybrid` |
| MCP Server | JSON-RPC 2.0 tools (`ground`, `cite`, `search`, `hybrid_search`, `resolve_entity`) over HTTP or stdio |
| Connector Hub | Schema-first introspection (`relational` / `catalog` / `api` / `objectstore` / `iceberg` / `glue` / `hive`; EE adds `streaming` / `snowflake` / `salesforce` / `warehouse` / `sharepoint`) and markdown/text/HTML/PDF/image document binding with `artifactDigest`, a pluggable IE provider and an external OCR provider, without copying data |
| Column Lineage | Source column → ontology concept/property with transform, confidence, unmapped columns and orphan rules (`POST /lineage/columns`) |
| Ontology Studio | Read-only model/lineage/usage and change-impact view (`GET /studio`, `/studio/model`, `/studio/impact`) |
| SHACL Export | Deterministic Turtle NodeShapes/PropertyShapes from ontology concepts, properties and relations (`GET /interop/shacl/{namespace}`) |
| SPARQL | Read-only SPARQL 1.1 subset (SELECT/BGP/FILTER/PREFIX/LIMIT) over assertions (`GET/POST /sparql`) |
| Action Runtime | Governed webhook actions with approval binding, SSRF guard and full audit (`/actions*`) |
| Grounding | Purpose-scoped Bundle assembly: intent + assertions + evidence + policy + conflict/gap |

## DSL compiler (SDK type generation)

Domain types are generated by the DSL compiler from the core repository (a dependency-free, Apache-clean standalone DTO):

```bash
# Generate Go types + JSON Schema from a Semantic Contract DSL document
cd ../GNOSIVELA/backend
go run ./cmd/gnosivela-gen -in ../../GNOSIVELA/contracts/examples/supplier.dsl -out ../../GNOSIVELA-open/sdk/go/gnosivela/gen -package gen

# Python + TypeScript DTOs (dataclasses / interfaces)
go run ./cmd/gnosivela-gen -in ../../GNOSIVELA/contracts/examples/supplier.dsl -out ../../GNOSIVELA-open/sdk/python/gnosivela -lang python
go run ./cmd/gnosivela-gen -in ../../GNOSIVELA/contracts/examples/supplier.dsl -out ../../GNOSIVELA-open/sdk/typescript/src -lang typescript
```

Reference generated types live at `sdk/go/gnosivela/gen/` (Go + JSON Schema),
`sdk/python/gnosivela/gen_supplier.py` and `sdk/typescript/src/gen_supplier.ts`.

The generated `gen.Supplier` and similar types map one-to-one to core semantic objects for strongly typed client-side modeling.

## Using the SDK

```go
import gnosivela "github.com/axisvela/GNOSIVELA-open/sdk/go/gnosivela"

c := gnosivela.New("http://localhost:8080")

res, err := c.OntologyCreate(ctx, dslDoc)      // create ontology from DSL
matches, err := c.EntityResolve(ctx, "ACME")   // resolve an entity
a, err := c.AssertionPropose(ctx, assertion)   // propose a knowledge claim
```

## Agent framework adapters

Dependency-free adapters call the governed control-plane API and never copy
semantics into the agent framework:

- Python: `gnosivela.integrations.tool_specs` (neutral), plus
  `langchain_tools` / `llama_index_tools` which return native tools when those
  packages are installed and neutral specs otherwise.
- TypeScript: `@axisvela/gnosivela/integrations` exports `toolSpecs`,
  `openAIToolDefinitions` (function-calling schema) and `toolHandlers`
  (name → invoke map), plus `langchainTools` / `llamaIndexTools` which return
  native tools when `@langchain/core` / `llamaindex` are installed and neutral
  specs otherwise.

Both expose `ground`, `cite`, `search`, `hybrid_search` and `resolve_entity`.

Native adapter matrix tested locally:
- Python 3.12.8: `langchain-core 1.7.0` (`StructuredTool`), `llama-index-core 0.14.25` (`FunctionTool`).
- Node 22: `@langchain/core 1.3.0` (`DynamicStructuredTool`), `llamaindex 0.12.1` (`FunctionTool`).

Native tests skip automatically when a framework is absent. These adapters
ship in v1.6.0.
